1 · Parser parity — is it the right machine?

Bridge/Format.lean · 232 lines · axioms [propext]

defparseEntries · tableOfF · encodeEntry
Entry := Option (Nat × Bool × Bool)      -- (next-state index, write, dir-is-right)
parseEntries : List Char → Option (List Entry)
  []                        ↦ some []
  '_' :: rest               ↦ parseEntries rest          -- group separator
  '-'::'-'::'-':: rest      ↦ none-entry :: rest          -- the halt cell
  w :: d :: s :: rest       ↦ decode via symOf/dirOf/stOf  -- e.g. '1','R','B'
tableOfF f := [encode (f A 0), encode (f A 1), …, encode (f F 1)]  -- row-major
variablemeaning
w, d, sone entry's three characters: write symbol, direction, next state
fany candidate transition function being encoded for comparison
theoremparse_ok · parse_detects_corruption · instr_unique
parse_ok : parseEntries codeChars = some (tableOfF instr)      -- by decide
parse_detects_corruption : parseEntries corruptedChars ≠ some (tableOfF instr)
instr_unique : parseEntries codeChars = some (tableOfF f) → f = instr

Proof. parse_ok is kernel computation over a 41-character list (over List Char, not String — String.toList drags in Classical.choice). The corruption control flips one character and proves the parse differs, so the theorem cannot pass vacuously. instr_unique chains injectivity of the encoding (stIdx_inj, dirR_inj, encodeEntry_inj, tableOfF_inj — finite case analyses) so table equality pins down the function itself. Both machines get the same treatment.

2 · The incision layer — watch only the boundary

Bridge/Incision.lean · 294 lines

The death set, made exact

theoremDead · Boundary · astep_eq_none_iff
Dead s     := s.m = 0 ∨ (s.m = 2 ∧ s.a ≤ 1)     -- decidable
Boundary s := s.m ≤ 2
astep_eq_none_iff : astep s = none ↔ Dead s
safeOrbitA_iff_avoids_death : SafeOrbitA ↔ ∀ n s, aorbit n = some s → ¬ Dead s

Proof. Unfold the if-chain of astep, four by_cases branches, omega on atoms only — an omega asked to prove a positive ∧/∨ silently imports Classical.choice, so compound goals are split first (constructor <;> omega).

The volley — event-skipping in closed form

defvolleyvolley_interior · aiter_volley
volley (a, m, c) := if m ≤ 2 then (a, m, c)
                    else (a, 2 − m % 2, c + 3·⌊(m−1)/2⌋)
volley_interior : 3 ≤ m → volley (a,m,c) = volley (a, m−2, c+3)  -- it IS the recursion
aiter_volley    : ∃ j, aiter j s = some (volley s)               -- and it's reachable
variablemeaning
jnumber of hydra steps skipped: ⌊(m−1)/2⌋, proved by fuel induction on m
2 − m % 2the landing boundary value: odd m → 1 (merge next), even m → 2 (drop next)

The event theorem

theoremeventSafe_iff_safeOrbitA · eventSafe_nonhalting
estep s  := (astep s).map volley          -- one boundary rule + one whole volley
eorbit 0 = some (volley (2,7,2)) ;  eorbit (k+1) = (eorbit k) >>= estep
EventSafe := ∀ k, eorbit k ≠ none

eventSafe_iff_safeOrbitA : EventSafe ↔ SafeOrbitA
eventSafe_nonhalting     : EventSafe → ¬ RawHalts blankStart

Proof, both directions by orbit interleaving. (→) invariant: every aorbit point has its volley on the event orbit — interior steps keep the same volley (volley_interior), boundary steps advance one event. (←) invariant: every event point is itself an aorbit point (aiter_volley + aorbit_add_aiter). So the two processes die together: checking only at incisions is sound and complete. Measured: event 16 ≈ raw step 10⁸; event 20,000 ≈ raw step 10⁷⁰⁴⁶.

3 · The hydra bridge — is it *the* conjecture?

Bridge/Conjecture.lean · 201 lines

defhydraNext · HydraState · hydraStep · HydraSafe
hydraNext b := b + b / 2                        -- H(b) = ⌊3b/2⌋
HydraState  := { b : Nat, heads : Nat }
hydraStep s := if s.b % 2 = 0     then some (H b, heads + 2)
               else if 2 ≤ heads then some (H b, heads − 1)
               else none                        -- odd value, starving counter
hydraOrbit 0 = some (12, 2) ;  HydraSafe := ∀ k, hydraOrbit k ≠ none
theoremRelHA · relHA_step · hydraSafe_nonhalting
RelHA s h := (s.m = 1 ∨ s.m = 2) ∧ s.c % 3 = 2
           ∧ h.b = s.m + 2·(s.c − 2)/3 + 5     -- the change of variables
           ∧ h.heads = s.a                      -- machine counter = heads

relHA_step : RelHA s h → (both die) ∨ (∃ s' h', both step ∧ RelHA s' h')
hydraSafe_iff_safeOrbitA : HydraSafe ↔ SafeOrbitA
hydraSafe_nonhalting : HydraSafe → ¬ RawHalts blankStart
variablemeaning
b = m + 2(c−2)/3 + 5the hydra value hidden in the record: pre-volley block length + 5
c % 3 = 2boundary invariant: every event state's c has this residue — it makes (c−2)/3 exact
parityb even ⇔ m = 1 ⇔ merge (+2) · b odd ⇔ m = 2 ⇔ drop (−1)

Proof. Lock-step simulation: for merges and live drops, the closed forms of estep reduce both sides and omega verifies the b-arithmetic; deaths coincide exactly (drop needs a ≥ 2 ⇔ odd step needs heads ≥ 2).

The honest delta. The wiki's process dies at counter = 0; ours at ≤ 1, one drop earlier, because Realizes needs a non-empty counter block (conjunct ② of the grammar). So HydraSafe is possibly strictly stronger than the community statement — documented everywhere the claim appears; closing the a = 0 grammar case is open work.

What exists: exact charts

defsimplexChart · log2Chart · h2Chart
simplexChart (a,m,c) := (a/Σ, m/Σ, c/Σ)  as exact Frac, Σ = a+m+c
  -- simplexChart_sum : numerators sum to the common denominator
log2Chart := (log₂(a+1), log₂(m+1), log₂(c+1))     -- additive shadow of growth
h2Chart   := (a − c, Σ + 1)                        -- upper-half-plane surrogate
  -- h2Chart_y_pos : the y-coordinate is always positive (a real ℍ² point)

Exact rational/integer counterparts of the Python atlas charts. The death condition m = 0 is literally a face of the simplex: “the orbit dies” becomes “the trajectory touches the wall.”

The proposed program, honestly framed

proposedincision geometry

Orbit values explode like 1.5ᵏ, so Euclidean plots degenerate; the proposal is that log / projective / hyperbolic coordinates are where a machine-characteristic incision figure lives. Three tiers, in increasing ambition:

tierclaimstatus
certified accelerationboundary-only checking, event costs in closed formproven (§2) + being extended now
empirical atlasincision figures match within delta-rule familiesfirst pass done (stage756): 3+2 machines pair up; raw charts need log scaling
invariant regionsan estep-invariant region at positive distance from the death face ⇒ unconditional non-haltingopen; impossible for Antihydra-class machines unless the conjecture falls — scoped to cohort machines whose clouds look confined
No known invariant separates Antihydra's orbit from its death set — if one existed the conjecture would be solved. Tier 3 is a search, not a promise; a null result is a publishable finding.
